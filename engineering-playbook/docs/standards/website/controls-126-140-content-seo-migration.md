# Content quality, SEO, and migration safety controls 126-140

[Standard index](../website-engineering-standard.md) | [Previous module](controls-111-125-performance.md) | [Next module](controls-141-150-release-operations.md)

## Controls

126. Every page and reusable content type has a named content owner, purpose, intended audience, update trigger, and review date.
127. Professional, legal, medical, financial, statistical, testimonial, case-result, and advertising claims receive qualified factual and policy review.
128. Each indexable page provides distinct, useful, audience-centered value and is not a thin, duplicated, doorway, or keyword-swapped page.
129. Titles, primary headings, descriptions, link text, and social metadata are accurate, unique where appropriate, and generated from controlled rules.
130. Each indexable page has one intended canonical URL, and protocol, host, trailing-slash, parameter, archive, and duplicate variants resolve consistently.
131. Robots directives, sitemap contents, crawl access, feeds, and indexability are intentional for every environment and content type.
132. Internal navigation and contextual links expose important content, avoid orphan pages, and use understandable link text.
133. Organization, person, local business, article, breadcrumb, FAQ, review, and other structured data are used only when supported by visible truthful content and current eligibility rules.
134. Existing URLs are preserved when practical; URL changes require a documented business reason rather than aesthetic preference.
135. The redirect plan covers every old URL that will not return the intended content at the same URL, including assets and important external campaign links where relevant.
136. Each redirect is permanent when appropriate, reaches the closest relevant final URL in one hop, preserves necessary parameters, and ends at a successful indexable response.
137. Staging protections are verified before content entry and fully removed at launch; production noindex, blocked resources, and placeholder canonicals are release blockers.
138. Migrated images and documents use owned URLs, correct file types and dimensions, useful filenames where practical, accessible text alternatives, and tested inbound links.
139. Prelaunch and postlaunch crawls compare old and new inventories for status codes, redirects, canonicals, titles, headings, metadata, indexability, internal links, and missing assets.
140. Search Console, analytics, rankings for material queries, crawl errors, sitemap processing, index coverage, and important landing pages are monitored after launch with an escalation owner.

## Applying this module

Record status, evidence or Not Applicable rationale, risk, owner, tracked work, target date, verification method, and recheck trigger for every applicable control. Store project-specific decisions and evidence locations in the project's `AGENTS.md` and linked state files.
