# Project intake record

When copied to `docs/project/project-intake.md`, the project coordinator is at `../../AGENTS.md`.

The intake questions are split by lifecycle phase so a new task can read the current gate completely without loading one oversized file. Use exact values where known. Use `UNANSWERED` when a decision is required and `N/A - [reason]` only when genuinely outside scope.

## Intake modules

1. [Phase 0 - identity, ownership, and boundaries](project-intake/phase-0.md)
2. [Phase 1 - discovery, users, data, and existing reality](project-intake/phase-1.md)
3. [Phase 2 - scope, architecture, security, and quality](project-intake/phase-2.md)
4. [Phase 3 - delivery plan and authorization](project-intake/phase-3.md)
5. [Phase 6 - release and operations readiness](project-intake/phase-6.md)

## Loading rule

Read this index and the module for the earliest incomplete phase. Read later-phase modules only when a present safety, legal, architectural, or scope decision depends on them. A full project audit must read every module in order.
